# Standard methods: Delete

## Guidance

- Delete **must** use `DELETE` on the instance path.
- Successful Delete **must** return **204 No Content** with an empty body.
- Delete **must not** take a request body.
- From the public API's perspective, Delete is **final**. There is no public
  restore path of any kind:
  - Subsequent Get of the same id **must** return `404` (indistinguishable from
    never existing)
  - Deleted resources **must not** appear in List
  - The public API **must not** provide undelete, restore, un-archive, or
    expunge methods (including colon custom methods)
  - The public API **must not** expose soft-delete fields (`delete_time`) or a
    `show_deleted` flag
  - OpenAPI summaries and descriptions **must not** promise restore, undelete,
    or revival of a deleted resource
- PUT Replace after Delete **must not** be documented or implemented as
  restoration of the deleted resource. If the path is a singleton that can be
  created again, that is a **new** create (new lifecycle), not undelete of the
  prior resource—see [AIP-134](./0134.md) and [AIP-156](./0156.md).
- Backends **may** retain tombstones internally for audit or deferred purge;
  that retention **must not** be observable or reversible through the public
  API.

### Example

```http
DELETE /beta/books/book_7f3a9c2e1d0b
```

```http
HTTP/1.1 204 No Content
```

```http
GET /beta/books/book_7f3a9c2e1d0b
```

```http
HTTP/1.1 404 Not Found
Content-Type: application/problem+json

{
  "title": "Not Found",
  "status": 404,
  "detail": "Book book_7f3a9c2e1d0b was not found.",
  "code": "not_found"
}
```
