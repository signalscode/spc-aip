# Standard methods: Update and Replace

Public APIs use two write styles: partial Update and full Replace.

## Guidance

### Update (PATCH)

- Partial updates **must** use `PATCH` on the instance path.
- There is **no** `update_mask` / field-mask query parameter.
- Update bodies **must** follow [JSON Merge Patch](https://datatracker.ietf.org/doc/html/rfc7396)
  semantics ([RFC 7396](https://datatracker.ietf.org/doc/html/rfc7396), formerly
  RFC 7386): a JSON object that describes changes by example against the
  current resource.
- Merge rules (per RFC 7396):
  - Members present in the patch with a non-null value are set / replaced
    (including `false`, `0`, and `""` when those are valid for the field)
  - Members present with JSON `null` are **removed** from the target
  - Members omitted from the patch are left unchanged
  - Nested objects are merged recursively
  - Arrays are replaced as a whole (not merged element-wise)
- The patch object **must not** include read-only fields such as `id`,
  `created_timestamp`, or `updated_timestamp`. If sent, servers **must**
  ignore them or reject the request ([AIP-129](./0129.md)).
- Content-Type is **not** significant for Update. Clients **may** send
  `application/json`, `application/merge-patch+json`, or omit a subtype
  detail. Servers **must** apply merge-patch semantics to a JSON object body
  and **must not** reject a valid merge patch solely because the Content-Type
  is not `application/merge-patch+json`.
- Do **not** use JSON Patch ([RFC 6902](https://datatracker.ietf.org/doc/html/rfc6902))
  operation arrays for public Update.
- Response body **must** be the updated resource.
- State transitions that are product actions (pause, resume, cancel) **must
  not** be modeled as PATCH field writes; use [custom methods](./0136.md).

```http
PATCH /beta/books/BRAC_HS4_ug
Content-Type: application/json

{
  "name": "Les Misérables (Revised)",
  "title": null
}
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": "BRAC_HS4_ug",
  "name": "Les Misérables (Revised)",
  "created_timestamp": "2021-01-01T00:00:00Z",
  "updated_timestamp": "2021-06-01T12:00:00Z"
}
```

### Replace (PUT)

- PUT is **allowed** and expected for:
  - Singleton upsert: create if the singleton does not exist, or completely
    replace the current (non-deleted) representation
  - Idempotent association attach (see [AIP-124](./0124.md))
- Replace **must not** restore a deleted resource. After Delete, PUT on the
  same path is a new create (new lifecycle), not undelete of the prior
  resource—see [AIP-135](./0135.md). Operation docs **must not** say
  “restore.”
- Replace request bodies **must** carry the full replaceable field set for that
  surface.
- PUT paths for parent-scoped singletons **must** include the parent `{id}`.

```http
PUT /beta/books/BRAC_HS4_ug/settings
Content-Type: application/json

{ "is_active": true, "prompt": "You are a helpful assistant." }
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "is_active": true,
  "prompt": "You are a helpful assistant.",
  "created_timestamp": "2021-01-01T00:00:00Z",
  "updated_timestamp": "2021-06-01T12:00:00Z"
}
```
