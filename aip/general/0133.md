# Standard methods: Create

## Guidance

- Create **must** use `POST` on the collection path: `/beta/{collection}`.
- Successful Create **must** return **201 Created**.
- The request body **must** be a dedicated create request object (flat JSON),
  not a nested `{ "book": { ... } }` envelope.
- The server assigns `id`. Clients **must not** supply `id` on create.
- The response body **must** be the created resource ([AIP-129](./0129.md)).

### Multipart Create

Create **may** use `multipart/form-data` when at least one creation variant
needs a binary file part. A Create that never accepts a required file
**must** stay JSON. Non-file variants **may** share the same multipart
Create when they create the same resource.

When multipart is used:

- Stay on the collection Create path. Do **not** invent `:upload` only to keep
  Create JSON-only ([AIP-136](./0136.md)).
- Use flat form parts (no nested resource envelope).
- Document accepted media types and size limits; the total body limit **must**
  allow the advertised max file plus multipart overhead.
- Enforce variant/kind part sets in validation, not only in prose
  ([AIP-193](./0193.md)).
- Reject unexpected parts, including `id` and timestamps ([AIP-129](./0129.md)).
- Failures **must not** leave a created resource or unattached blob.
- Success is still **201** with the created resource as JSON.

Prefer `:upload` (or resumable upload) only for multi-step or resumable
transfer after Create.

### Example (JSON)

```http
POST /beta/books
Content-Type: application/json

{ "name": "Les Misérables", "title": "A Novel" }
```

```http
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": "AUIAE-DUXA",
  "name": "Les Misérables",
  "title": "A Novel",
  "created_timestamp": "2021-01-01T00:00:00Z",
  "updated_timestamp": null
}
```

### Example (multipart)

```http
POST /beta/knowledge-bases/BUIAC-DUXA/documents
Content-Type: multipart/form-data; boundary=boundary

--boundary
Content-Disposition: form-data; name="name"

Pricing FAQ
--boundary
Content-Disposition: form-data; name="kind"

file
--boundary
Content-Disposition: form-data; name="file"; filename="pricing.pdf"
Content-Type: application/pdf

...pdf bytes...
--boundary--
```

```http
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": "BUIAE-DUXA",
  "name": "Pricing FAQ",
  "kind": "file",
  "sync_status": "in_progress"
}
```
