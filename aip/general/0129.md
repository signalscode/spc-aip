# Server-owned values and defaults

Some fields are owned by the server. Clients must not treat them as writable
inputs.

## Guidance

- Server-owned fields **must** be documented as read-only in OpenAPI
  (`readOnly: true`), for example `id`, `created_timestamp`,
  `updated_timestamp`.
- Create and Replace request schemas **must not** require read-only fields.
  Clients **should** omit them; servers **must** ignore them if sent.
- Update (JSON Merge Patch) bodies **must not** rely on patching read-only
  fields; servers **must** ignore or reject those members ([AIP-134](./0134.md)).
- Do not silently rewrite client-authored mutable fields in responses except
  for documented normalizations (for example E.164 phone formatting).
- Defaulting **may** occur server-side; responses **should** return the
  effective stored value.

### Example

```http
POST /beta/books
Content-Type: application/json

{ "name": "Les Misérables" }
```

```http
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": "AUIAE-DUXA",
  "name": "Les Misérables",
  "created_timestamp": "2021-01-01T00:00:00Z",
  "updated_timestamp": null
}
```

```yaml
Book:
  type: object
  required: [id, name, created_timestamp]
  properties:
    id:
      type: string
      readOnly: true
      description: Opaque public identifier of the book.
      example: AUIAE-DUXA
    name:
      type: string
    created_timestamp:
      type: string
      format: date-time
      readOnly: true
    updated_timestamp:
      type: string
      format: date-time
      nullable: true
      readOnly: true
```
