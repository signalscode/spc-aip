# Naming conventions

## Guidance

| Surface | Convention |
| ------- | ---------- |
| URL collection segments | plural `kebab-case` |
| URL custom verbs | `:` + `camelCase` verb (`:clone`, `:generateSummary`) |
| JSON fields | `snake_case` |
| Schema / type names | PascalCase |
| Enum wire values | `snake_case` strings |
| OpenAPI `operationId` | `{Version}_{camelAction}` |
| Operation display name | `{Version}{PascalAction}` |
| OpenAPI tags | human-readable title case phrases |

- American English spelling.
- Treat multi-letter product acronyms as words in PascalCase type names when
  needed (`HttpClient`, `SmsChannel`), except keep conventional `ID` suffixes
  on identifier fields (`publisher_id` on the wire). Public ids are opaque
  strings ([AIP-122](./0122.md)).

### Example

```http
GET /beta/phone-numbers/pn_7f3a9c2e1d0b
POST /beta/books/book_7f3a9c2e1d0b:generateSummary
```

```yaml
operationId: Beta_generateBookSummary
tags: [Books]
```

```json
{ "phone_number_id": "pn_7f3a9c2e1d0b", "llm_model": "gpt-4.1-mini" }
```
