# Naming conventions

## Guidance

| Surface | Convention |
| ------- | ---------- |
| URL collection segments | plural `kebab-case` |
| URL custom verbs | `:` + `kebab-case` verb (`:clone`, `:generate-summary`) |
| JSON fields | `snake_case` |
| Schema / type names | PascalCase |
| Enum wire values | `snake_case` strings |
| OpenAPI `operationId` | `{Version}_{camelAction}` |
| Operation display name | `{Version}{PascalAction}` |
| OpenAPI tags | human-readable title case phrases |

- American English spelling.
- Prefer well-known abbreviations in field names (`config`, `id`, `delay_ms`) —
  see [AIP-140](./0140.md) and [AIP-141](./0141.md).
- Treat multi-letter product acronyms as words in PascalCase type names when
  needed (`HttpClient`, `SmsChannel`), except keep conventional `ID` suffixes
  on identifier fields (`publisher_id` on the wire). Public ids are
  `{type}_{object}` UID strings ([AIP-122](./0122.md)).

### Example

```http
GET /beta/phone-numbers/BRAB_JeAz9Q
POST /beta/books/BRAC_HS4_ug:generate-summary
```

```yaml
operationId: Beta_generateBookSummary
tags: [Books]
```

```json
{ "phone_number_id": "BRAB_JeAz9Q", "llm_model": "gpt-4.1-mini" }
```
