# AIP Purpose and Guidelines

AIPs (API Improvement Proposals) are the **source of truth** for Atonom public
HTTP/OpenAPI API design. Repositories such as `bff-public-api` implement these
rules in their endpoint contracts.

## Guidance

- Approved AIPs in `aip/general/` are mandatory for public endpoint design.
  Draft AIPs are guidance-in-progress and **must not** be treated as mandatory
  until approved (see [TODO.md](../../TODO.md) for open decisions).
- Apply only guidance relevant to JSON HTTP/OpenAPI contracts. Do not introduce
  protobuf-only constructs into Go endpoint definitions.
- If a BFF OpenAPI contract or repository convention conflicts with an AIP,
  **change the BFF to match the AIP** (or open an AIP amendment). Do not treat
  the live contract as overriding this guidance.
- Area-specific guidance does not exist in this fork; only `aip/general/` applies.
