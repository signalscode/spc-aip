# Pagination

List methods currently document offset pagination with `skip` and `limit`.

## Guidance (today’s `/beta` offset shape)

Until the TODO above is resolved, List contracts that use offset pagination
**should** follow this shape (illustrative for `/vN`, not a locked ban on
cursors):

- List requests accept:
  - `skip` (int, ≥ 0) — number of matches to skip; default 0
  - `limit` (int, ≥ 0, max 100) — page size; default 20
- List responses include:
  - `items` — page of results
  - `total` — total matches before pagination
  - `skip` — echoed skip
  - `limit` — echoed limit
- Do not introduce `page_token` / `page_size` / `next_page_token` on an existing
  offset-paginated surface without resolving the TODO (adding a second
  pagination model later is usually a breaking change — see [AIP-180](./0180.md)).
- Collections that are paginated **must** be paginated from the first public
  release of that collection; adding pagination later is a breaking change.
- Negative `skip` or `limit` **must** be rejected as invalid argument.

### Example

```http
GET /beta/books?skip=20&limit=20
```

```json
{
  "items": [],
  "total": 100,
  "skip": 20,
  "limit": 20
}
```
