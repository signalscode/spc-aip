# Documentation

## Guidance

- Every field on the public wire **must** have a human-readable description in
  the OpenAPI schema (`description`).
- Scalar fields **should** include an `example` unless a single enum value makes
  an example redundant.
- Every operation **must** have non-empty `summary` and `description`.
- Prefer precise product language; avoid vendor brand names that should stay
  out of customer-facing copy.

### Example

```yaml
Book:
  type: object
  properties:
    id:
      type: string
      readOnly: true
      description: Opaque public identifier of the book.
      example: AUIAE-DUXA
    name:
      type: string
      description: Display name of the book.
      example: Les Misérables
paths:
  /beta/books/{id}:
    get:
      summary: Get a book
      description: Return one book by id.
      operationId: Beta_getBook
```
