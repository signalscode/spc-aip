# Resource identity and paths

Resources are addressed by **opaque UID string ids** on versioned, kebab-case
collection paths. Display names are separate from identity.

## Guidance

### Paths

- Collection paths **must** be plural kebab-case under the API version:
  `/beta/books`, `/v1/phone-numbers`.
- Instance paths **must** use `{id}` (or a typed sibling such as `{shelf_id}`)
  as the path parameter name. Path id segments **must** be opaque UID strings.
- Nested resources **must** include the parent id in the path:
  `/beta/books/{id}/reviews/{review_id}`.
- Path segments **must not** use Google-style hierarchical `name` bindings
  (`{name=publishers/*/books/*}`).

### Identity fields

- Resources **must** expose a stable `id` field that is:
  - a **16-character UID string** on the public wire (see construction below)
  - **opaque** to clients (not a sequential integer clients should parse or
    enumerate)
  - read-only
- Resources **may** expose a human-readable `name` (display name). `name` is
  **not** the canonical resource path.
- Do **not** require clients to store hierarchical resource name strings as the
  primary identifier.
- Cross-resource references **should** use `*_id` UID string fields (for
  example `author_id`), not embedded resource objects and not public integer
  primary keys.
- Clients **must** treat ids as uninterpreted tokens: do not parse, increment,
  or infer ordering or cardinality from id contents.

### Opaque id construction

A public `id` or `*_id` **must** be the text form of a 12-byte UID:

- Bytes 0–3 are a type id (`uint32`), big-endian.
- Bytes 4–11 are the object id (`int64`), big-endian.
- The text form is unpadded base64url
  ([RFC 4648](https://datatracker.ietf.org/doc/html/rfc4648#section-5) section 5).
  Twelve bytes encode to exactly 16 characters.
- The alphabet is `A–Z`, `a–z`, `0–9`, `-`, and `_`. Text is case-sensitive.
- There is no type prefix, no checksum, and no spare bits.

The type id is packed into that `uint32`:

- Bits 31–16 are the module type. `0` names the module and is not an object
  type. Object types are `1..65535`.
- Bits 15–12 are the version nibble (`version & 0xF`). Nibble `0` is invalid.
- Bits 11–0 are the module id, `1..4095`. Module `0` is never assigned.

The object id **must** be the resource's positive internal integer key. Zero
and negative values are invalid. The type id is part of the value, so an id is
unique across resource types, not only inside one collection.

A decoder **must** require length 16, that alphabet, no `=` padding, a 12-byte
decode, and a re-encode that equals the input. It **must** reject an invalid
type id, module type `0`, and an object id that is not greater than 0. An id
that decodes as a different resource type is not an id of the resource being
addressed.

Producers **must** put only this text on the public wire. The raw integer key
stays off the public contract.

OpenAPI **should** set `pattern` to `^[A-Za-z0-9_-]{16}$`. That pattern checks
shape. The decoder rules above still apply.

Worked example: type id `135173` (module `5`, module type `2`, version nibble
`1`) and object id `1001` encode as `AAIQBQAAAAAAAAPp`.

### Examples

```http
GET /beta/books/AAIQBQAAAAAAAAPp
GET /beta/books/AAIQBQAAAAAAAAPp/settings
POST /beta/books/AAIQBQAAAAAAAAPp:clone
```

```json
{
  "id": "AAIQBQAAAAAAAAPp",
  "name": "Les Misérables",
  "author_id": "AAEQBAAAAAAAABOJ",
  "created_timestamp": "2021-01-01T00:00:00Z"
}
```
