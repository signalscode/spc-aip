# Custom methods

Custom methods express actions that are not standard CRUD.

## Guidance

- Use custom methods only when Create/Get/List/Update/Replace/Delete do not fit.
- HTTP **must** be `GET` for read-only retrieval side paths (for example
  download) and `POST` for anything with side effects.
- The URI **must** append a colon (`:`) plus the custom verb, so actions are
  never ambiguous with child collections:
  - Resource action: `/beta/books/{id}:clone`
  - Nested singleton action: `/beta/books/{id}/settings:reindex`
  - Collection action: `/beta/books:batch-delete`
- Do **not** use an extra path segment for the verb
  (`/books/{id}/clone` is wrong; `/books/{id}:clone` is correct). Path segments
  after the parent remain collection or singleton nouns only
  (`reviews`, `settings`).
- The verb in the URI **must** be `kebab-case` and match the verb used in the
  operation name (mapped to camelCase / PascalCase there as needed).
  - Single-word verbs: `:clone`, `:pause`, `:cancel`
  - Multi-word verbs: `kebab-case` after the colon (`:generate-summary`)
- Method names **should** be verb-oriented (`CloneBook`, `GenerateBookSummary`).
- Request/response bodies use dedicated request/response schemas as needed.
  Returning the resource is allowed (for example clone → 201 + resource).

### Why colon form

```http
# Child collection (noun, plural path segment)
GET /beta/books/{id}/reviews

# Custom method (verb, colon-delimited) — not a collection
POST /beta/books/{id}:clone
```

Without the colon, `/books/{id}/clone` is indistinguishable from a nested
resource named `clone`.

### Examples

```http
POST /beta/books/{id}:clone
POST /beta/books/{id}:pause
POST /beta/books/{id}:generate-summary
GET  /beta/reports/{id}:download
```

```http
POST /beta/books/AUIAE-DUXA:clone
```

```http
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": "AUIAE-I4TA",
  "name": "Les Misérables (copy)",
  "created_timestamp": "2021-06-01T12:00:00Z"
}
```
