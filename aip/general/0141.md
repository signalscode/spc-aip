# Quantities

Fields that represent a discrete quantity with a clear unit of measurement
include that unit as a suffix. Prefer well-known abbreviations; do not pluralize
abbreviations (aligned with [google.aip.dev/141](https://google.aip.dev/141)).

## Guidance

- Quantity fields **must** include the unit as a field-name suffix.
- When a generally accepted abbreviation exists among software developers, use
  it instead of the full unit word. Abbreviations **must not** be pluralized.

  | Prefer | Instead of |
  | ------ | ---------- |
  | `_ms` | `_milliseconds` |
  | `_s` | `_seconds` (integer second counts) |
  | `_min` | `_minutes` |
  | `_h` | `_hours` |
  | `_km` | `_kilometers` |
  | `_px` | `_pixels` |
  | `_b` / `_kb` / `_mb` / `_gb` | `_bytes` / `_kilobytes` / … when abbreviated |

- Examples: `delay_ms`, `ring_time_limit_ms`, `duration_min`, `distance_km`,
  `width_px`.
- Counts of items (no physical unit) **should** use a `_count` suffix
  (`node_count`), not a `num_` prefix.
- Inverse / rate units **should** spell out `per` rather than inventing opaque
  acronyms: `speed_miles_per_hour` (not `speed_mph`),
  `event_count_per_hour`.
- Absolute timestamps remain RFC 3339 strings ([AIP-142](./0142.md)); do not
  encode wall-clock instants as `_ms` epoch fields on this public surface.

### Example

```json
{
  "delay_ms": 1000,
  "ring_time_limit_ms": 10000,
  "duration_min": 30
}
```
