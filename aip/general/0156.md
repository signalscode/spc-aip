# Singleton resources

Singletons are unique under a parent and have no child id segment.

## Guidance

- Singleton paths omit a child resource id, for example:
  `/beta/books/{id}/settings`.
- Singletons **should** support:
  - `GET` — read current settings
  - `PUT` Replace — create if absent, or completely replace if present
  - `PATCH` Update — partial update when useful
  - `DELETE` — remove settings (204); Delete is final — not restorable via the
    public API ([AIP-135](./0135.md))
- There is no separate Create path for singletons; PUT Replace covers first-time
  create. After Delete, a later PUT is a new create (new lifecycle), not
  undelete. Do not document Replace as “restore.”
- Distinct singleton kinds use separate path segments (`settings`, `cover`, …),
  not a single `{settings_id}` collection.

### Example

```http
GET /beta/books/AAIQBQAAAAAAAAPp/settings
PUT /beta/books/AAIQBQAAAAAAAAPp/settings
PATCH /beta/books/AAIQBQAAAAAAAAPp/settings
DELETE /beta/books/AAIQBQAAAAAAAAPp/settings
```
