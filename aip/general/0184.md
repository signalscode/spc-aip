# API version identifiers

## Guidance

- The version channel is the first path segment after the host:
  `/beta/...`, `/v1/...`, `/v2/...`, and so on.
- That path prefix is the wire version identifier and the stability signal
  (see [AIP-181](./0181.md)).
- Endpoint packages and generated clients **should** organize by the same
  channel (`alpha`, `beta`, `vN`).
- `operationId` / operation name prefixes **must** match the path channel
  (`Beta_...` / `Beta...`, `V1_...` / `V1...`).
- OpenAPI `info.version` and snapshot filenames are document metadata only.
  They **must not** be treated as the wire version or stability signal when they
  disagree with the path prefix.

### Example

```http
GET /beta/books/AUIAE-DUXA
GET /v1/books/AUIAE-DUXA
```

```yaml
openapi: 3.1.0
info:
  title: Public API
  version: 1.4.2   # document revision only; not the wire channel
paths:
  /v1/books/{id}:
    get:
      operationId: V1_getBook
```
