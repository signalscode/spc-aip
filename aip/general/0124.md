# Resource association

Some relationships attach an existing child resource to a parent without owning
the child's lifecycle.

## Guidance

- Prefer **PUT Replace** on an association path to attach or upsert:
  `/beta/books/{id}/shelves/{shelf_id}`.
- Prefer **DELETE** on the same path to detach.
- Do **not** require a separate Create on the parent path when the child already
  exists as a top-level resource.
- Association Replace **must** be idempotent: repeating the same PUT leaves the
  association in place.
- Owned nested collections still use standard Create/List/Get/Update/Delete on
  the nested path.

### Example

```http
PUT /beta/books/AUIAE-DUXA/shelves/AUIAC-OJNQ
DELETE /beta/books/AUIAE-DUXA/shelves/AUIAC-OJNQ
```
