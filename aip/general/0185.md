# API versioning

## Guidance

- Clients select a stability channel by path prefix (`/beta`, `/v1`, `/v2`, …).
  See [AIP-181](./0181.md).
- **Stable channels** (`/v1`, `/v2`, …):
  - Breaking changes **must** introduce a new path prefix (for example `/v2`),
    not silently break the existing prefix.
  - Non-breaking additive changes **may** land in place on the current stable
    prefix.
- **Preview / experimental channels** (`/beta`, `/alpha`):
  - Breaking changes **may** occur in place on that prefix.
  - Clients **must not** assume long-term compatibility on these prefixes.
- Moving a surface from preview to stable **must** publish it under a new
  stable prefix (typically `/v1`), not by renaming compatibility expectations
  while keeping `/beta` in the path.
- East-west Connect/protobuf versioning is separate from this public HTTP
  versioning story.

### Example

```http
# Preview — may change in place
PATCH /beta/books/book_7f3a9c2e1d0b

# Stable — breaking change requires /v2, not in-place break of /v1
PATCH /v1/books/book_7f3a9c2e1d0b
PATCH /v2/books/book_7f3a9c2e1d0b
```
