# Filtering

## Guidance

- Simple filters **should** be explicit query parameters on List methods.
- Filter parameters **must** use `snake_case` names.
- Do not require a single unstructured `filter` string expression language
  unless a resource explicitly adopts one.
- Changing filter parameters while paginating is allowed; page contents and any
  total count reflect the filtered set.
- An empty query parameter is ignored. `?area_code=` is the same as omitting
  `area_code`. The server **must** not apply that parameter and **must** not
  return a validation error. The same rule applies to pagination parameters:
  an empty `skip` or `limit` uses the default ([AIP-158](./0158.md)).
- Patterns, enums, formats, and string length bounds apply only to a
  non-empty value. When a string constraint describes that value, the
  published schema **must** also accept empty, so it does not reject a
  request the server ignores. For a pattern, use an optional group, for
  example `^([2-9][0-9]{2})?$`. Numeric parameters stay integers. An empty
  value is ignored before the numeric bound is applied.
- Pagination field names follow [AIP-158](./0158.md) (pagination model is
  undecided for `/vN`; examples below use today’s `/beta` `skip` / `limit`).

### Example

```http
GET /beta/books?author_id=AQIAC-DUXA&skip=0&limit=20
```

```json
{
  "items": [{ "id": "AUIAE-DUXA", "name": "Les Misérables", "author_id": "AQIAC-DUXA" }],
  "total": 3,
  "skip": 0,
  "limit": 20
}
```
